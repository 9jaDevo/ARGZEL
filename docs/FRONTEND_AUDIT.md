## Confirmation and privacy boundary

Capture and parsing never create a reminder. Only Confirm calls save; Review changes returns to preview. In the fixture run, the count was **zero saves before confirmation**, then **one save after confirmation**. A subsequent edit left that save count at one, with the same reminder ID and completed status. Deletion required the existing confirmation dialog. Cancelling the dialog with Escape restored focus to its trigger.

No raw recording is written to disk by the capture code. API credentials remain in httpOnly cookies; passwords are not stored in browser storage. The fixture workflow used synthetic account data and an in-memory provider/database substitute, not Atlas or Resend. No real emails or provider inference calls were made for this audit's UI checks.
